# 多数据集的统一操作手册

## 一套固定约定

**每个数据集 / split 准备一份任务文件、一套原图；整个项目选择一个输出根目录。工具为每份任务文件自动建立独立的标注工作文件夹。**

推荐目录如下，具体文件夹名称可自行修改：

```text
my_annotation_project/
├── datasets/
│   ├── dataset_a/
│   │   ├── tasks.jsonl
│   │   └── images/
│   │       ├── image_001.jpg
│   │       └── image_002.jpg
│   └── dataset_b/
│       ├── train.jsonl
│       ├── validation.jsonl
│       └── images/
└── annotations/                            # 界面选择的输出根目录
    ├── dataset_a--<10位标识>/
    ├── dataset_b--<train对应标识>/
    └── dataset_b--<validation对应标识>/
```

输出标识由**任务文件的完整路径 + 文件内容校验**计算。不同文件夹里都叫 `tasks.jsonl`，或两个数据集都有 `sample_001` 和 `image_001.jpg`，也不会把输出混在一起。修改任务文件内容、改名或移动任务文件，会建立新工作文件夹，原文件夹保留，不自动合并。建议标注开始后固定任务文件及其位置。

原图目录单独绑定和记忆，不参与这份任务文件的内容校验。切换到新的数据集不会继承上个数据集的原图目录，避免把同名图片错配。重新打开原来的任务文件会恢复它自己记住的原图目录、已提交结果和草稿。

## 打开的文件是什么

首选 **JSONL：一行一个任务对象**，UTF-8 编码，没有外层方括号，各行之间不写逗号。不是一个图片文件夹，也不是一个包含所有图像的压缩包。

推荐自有数据使用下面的字段：

```jsonl
{"id":"a_001","image":"images/image_001.jpg","question":"右下方标牌上的数字是多少？","answer":"30","source_dataset":"dataset_a"}
{"id":"a_002","image":"images/image_002.jpg","question":"门前两副春联合计有多少个字？","answer":"14","source_dataset":"dataset_a"}
```

| 输入字段 | 建议 | 说明 |
| --- | --- | --- |
| `id` | 必填且唯一 | 源任务 ID；也可使用 `sample_id`，后者优先 |
| `image` | 必填 | 图片路径；相对路径以这份任务文件所在文件夹为起点 |
| `question` | 必填 | 显示给标注员的问题 |
| `answer` | 有参考答案时填写 | 提交前隐藏，提交成功后显示；缺失时保存为空字符串，不会生成答案 |
| `source_dataset` | 强烈建议 | 数据来源名称；没有时使用界面指定 / 自动识别的数据集名 |

`image` 写成 `images/image_001.jpg`，图像放在任务旁的 `images` 文件夹，就可以直接加载。若已有的文件只写图片名 `image_001.jpg`，加载后点「选择原图目录」定位该数据集的 `images` 文件夹即可。也支持完整绝对路径，但跨机器迁移时通常不如相对路径方便。

也支持以下格式，无须强制全部转成 JSONL：

- **JSON 数组**：`[{...}, {...}]`，与上述字段相同。
- **单条 JSON 对象**：适合检查 / 重标某个会话。
- **VisualProbe 原始 JSON**：`doc_id/problem/solution/images/data_source` 自动识别。
- **Human-Search-Traces 发布 JSONL**：会话可作为新任务输入，旧框 / 答案 / 评分不提前显示；加 `--review` 才进入只读检查。
- **旧标准任务 / VLM-R1**：兼容 `instruction` 和 `messages/images`，不需要再运行旧转换脚本才能使用。

任意未知数据集的私有嵌套结构不能凭空识别。若它既不符合上述格式，也没有统一的 image / question 字段，应先明确映射成上述通用任务结构。工具不会把整个任意文件夹里的 JSON 都猜测成任务。

## 从启动到提交的固定操作顺序

1. 启动 `python main.py`，或在 macOS 双击启动脚本。
2. 首次设置「输出根目录」，例如统一选择 `annotations`。后续数据集沿用这个根目录。
3. 如有需要，在顶部填写数据集名称；留空时优先从 `source_dataset` 自动识别，否则从任务文件 / 父文件夹识别。这个名称主要决定工作文件夹前缀，不覆盖输入中已有的真实来源字段。
4. 点击「加载 JSON / JSONL」，选择本次数据集 / split 的任务文件。
5. 如果图像未找到，点「选择原图目录」。缺图状态下提交按钮禁用，不会显示上一题图片冒充当前图。
6. 在左侧读问题，再移入画布搜索；离开画布时记录和计时一起暂停，返回后恢复。初始可看到整张原图，右键矩形放大、左键画证据框，恢复全图和删除使用界面按钮。可以标多个框，修改不会删除先前轨迹。
7. 点击「提交并评价」，用难度 / 置信度滑条评分；成功保存后显示参考答案并锁定，**停留本题**。
8. 点击「下一题 / 跳过」。不想标的题直接跳过，未提交的操作保存为草稿，不会伪装成已提交会话。

导航按钮只在数据集开头 / 结尾因没有前一题 / 后一题而禁用，不要求当前题必须有框或已经提交。界面跳转题号从 1 开始，程序参数 `--start-index` 从 0 开始。

## 输出文件保留在哪里

```text
annotations/dataset_a--<标识>/
├── workspace.json
├── sessions/
│   ├── a_001_idx0_v1.json
│   └── a_002_idx1_v1.json
├── .drafts/
│   └── <任务标识>.json
├── .metadata/
│   └── a_001_idx0_v1.json
└── exports/
    └── sessions.jsonl
```

| 位置 | 内容与保留方式 |
| --- | --- |
| `workspace.json` | 本地任务文件路径、校验、任务数、原图目录和工具版本；辅助配置，不是发布数据 |
| `sessions/*.json` | 一次成功提交一个文件，包含最终 11 字段；不覆盖已有文件 |
| `.drafts` | 未提交草稿，每 5 秒及切题 / 退出时保存；提交成功后清除相应草稿 |
| `.metadata` | 本地工具版本、原图尺寸、草稿恢复段数；不混入发布字段 |
| `exports` | 用户主动生成的 JSONL；不会代替 / 删除原始 sessions 文件 |

文件名中 `idx` 为原任务索引，`v` 为会话版本。已有 v1 不会在重启后被覆盖。对于直接载入的历史会话，例如 `...idx950_v1`，重新采集会从 `...idx950_v2` 起步，仍保留来源索引 950。

重新打开同一任务文件时，已提交题显示答案与已存框，并处于只读状态；未提交题恢复草稿，答案仍隐藏。需要独立的重复采集时应建立新的采集目录并明确批次，且不要把看过答案后的重标当作首次盲搜数据。

切换输出根目录不会搬迁或删除旧根目录内容。建议在开始一批标注前选定输出根目录；需要重新打开以前的结果时选回原根目录和任务文件。

## 导出与交接

界面点击「导出当前数据集 JSONL」，默认建议保存到本数据集的 `exports/sessions.jsonl`。只导出 `sessions` 内的成功提交，**不含草稿、界面配置或辅助元数据**。已有导出文件不会覆盖，请另选文件名，例如 `sessions_round2.jsonl`。

命令行等价操作如下，把数据集文件夹替换成界面所示的实际名称：

```bash
python tools/export_jsonl.py \
  "annotations/dataset_a--<标识>/sessions" \
  "annotations/dataset_a--<标识>/exports/sessions.jsonl"
python tools/audit_traces.py \
  "annotations/dataset_a--<标识>/exports/sessions.jsonl"
```

默认保留全部独立提交版本；只有明确需要对同一任务只取最高版本时才用 `--latest-only`。导出不会拼接不同会话的事件，也不会重写历史框。

建议备份**整个 `annotations` 根目录 + 固定任务文件 + 原图**。仅保存导出的 JSONL 足以保留最终会话结构，却无法保留尚未提交的草稿、目录配置和本地恢复信息。复制到另一台电脑后，若任务路径改变而出现新文件夹，旧结果仍在原文件夹，可用 `--review` 打开已有 JSON / 导出 JSONL 检查；不要通过改写记录里的 id 来强行合并。

## 坐标、频率与“完全兼容”的含义

- 原点始终是原图左上角，x 向右、y 向下；局部放大不会把坐标原点改到局部左上角。
- 时间为画布内的累计有效时间。离开画布暂停采样和计时，返回后继续；例如画布内 5 秒、外部停留 20 秒、再在画布内 3 秒，累计为 8 秒。
- 移动事件约每 100 ms 最多一条，约 10 Hz；按下、释放、进入、离开、开始 / 结束等事件即时记录，可以同一时间戳出现多条。
- 没有规定静止时也必须每 100 ms 补一条。历史连续 hover_move 间隔中位数为 106.8 ms，所以不应强行把原始轨迹当作均匀采样序列。
- 按钮、评分滑条、导航的点击坐标不采集。恢复全图和删除的结果分别记录语义事件，并不记录该按钮在屏幕上的位置；在画布外操作时，结果事件的时间保持在暂停值。
- 完全覆盖发布格式的 **11 个顶层字段、19 类事件以及它们不同的 bbox 形状、评分 null 约定、原图坐标和最后事件计时**。不是要求每个会话都必须出现全部 19 类事件。
- 历史未上传代码不能由数据唯一恢复。重建支持相同输出格式与已确认流程，不会刻意制造历史点框、负边界框、一像素取整误差或视图切换速度尖峰。

事件逐项定义见 [数据契约](data_contract.md)，从真实样例反推规则的证据见 [数据分析](reconstruction.md)。
