## 3. 七个有代表性的样例

### A. 单框、连续区域放大：1001

`visual_probe_train_1001_idx950_v1`，原图实测 **7497×5001**，问题询问右下绿色限速标志数字，答案为 `30`。共 143 个事件，17.56 秒。

关键过程：

| t（ms） | 事件 | 原图坐标 / 内容 |
| --- | --- | --- |
| 0.0 | canvas_enter | (172,1996)，随后进入 hover 搜索 |
| 3783.2 | zoom_start | (5035,3646) |
| 6742.9 | zoom_end | `[5035,3646,7497,4972]` |
| 13564.4 | 第二次 zoom_start | (5486,4097) |
| 14432.8 | 第二次 zoom_end | `[5486,4097,5787,4466]` |
| 16422.7 | down / create_start | 原图坐标 (5582,4211) |
| 17365.8 | create_end | `[5582,4211,5653,4281]` |
| 17559.2 | canvas_leave | 最后事件，对应 17.56 秒 |

最终框是 `[5582,4210,5653,4281]`。在原图上查看，这个约 71×71 的框确实覆盖数字 `30`，而不是整块黄色牌匾。两级缩放后的坐标仍处在原图约 x=5600、y=4200 的位置，直接证实输出不能使用显示控件坐标。

最终 y1 比 create_end 少 1，属于广泛存在的历史取整现象，不能解释为有一次未记载的人为调整。

### B. 双框计数：1004

`visual_probe_train_1004_idx1263_v1`，原图实测 **6000×4000**，问题询问门前红底春联有几个字，答案 `fourteen`。共 241 事件，27.65 秒。

最终框分别为 `[1992,1725,2093,2181]`、`[2360,1726,2441,2175]`。在原图上分别对应左联和右联。create_end 的 index 分别为 0 与 1。这支持多个空间分离证据可以分别标框，而不是强制用一个巨大包围框把中间无关区域全部圈进来。

但“8 条双框”不是“8 条都具有两个有效证据”：其中包含以下点框异常，不能直接拿多框数量当作高质量多证据样本统计。

### C. 误点击、编辑、删除后重画：1175

`visual_probe_train_1175_idx1127_v1`，问题询问黑色垃圾桶最下方文字，答案 `Since 1854`。43.24 秒、283 事件。

先创建 index 0 的文本框，再创建 index 1 的点框；随后选中 index 0，触发 resize 的 edit_start / edit_end，删除 index 0，再创建新的 index 1。最终留下一个点框 `[2042,2363,2042,2363]` 和一个有效文本框。

这个样例证明最终版允许编辑、删除和重画，也证明 `index` 随列表变化，不能当成永久 ID。新版保留修正操作的轨迹，但阻止点框进入最终结果。

### D. 最终框与事件数量不一致：1344

`visual_probe_train_1344_idx1264_v1`，车牌题，9.51 秒、81 事件。最终结果有一个车牌框与一个点框，但事件仅有一次 create_end。

这是唯一一条按 create_end / edit_end / delete_bbox 重放后框数与最终结果不一致的记录。由此无法可靠判断当时是否存在“按下即入列表、未释放就提交”等问题，工具不能凭空补一个创建事件。

### E. 空最终框：179

`visual_probe_train_179_idx345_v1`，询问右上段落的语言，答案 `Chinese and English`，6.20 秒、50 事件，没有任何 create_end，最终框为空。

它并非缺少 final_bboxes_pixels 字段，而是显式空列表。新版允许在确认后提交空框记录，审计发出提示；如果下游任务必须具有最终框，应显式筛选，不能把空框误当作整图框。普通跳过不会生成一个伪装成已完成的空框会话。

### F. 歧义评分：322

`visual_probe_train_322_idx257_v1`，询问 TISAK 亭左侧女士衣服颜色，参考答案 `white`。69.36 秒、460 事件，并且存在一个最终框。

其评价为 `is_ambiguous=true`、`difficulty_level=ambiguous`、`difficulty_score=null`、`confidence_score=null`。因此歧义不等于“没有框”，也不应强行编码为 difficulty=1 或 confidence=0。

### G. 真正的框调整：837

`visual_probe_train_837_idx756_v1`，警车文字题，参考答案 `POLIZEI`。26.74 秒、217 事件。先 create_end，再以 `mode=resize, handle=br` 调整右下角；全数据仅有的 9 个 edit_move 均在此样例。

编辑后的框应由 edit_end 覆盖对应 index，而不能总把最后一个 create_end 当成最终框。这也是新版统一编辑事件、增加按角点调整测试的直接依据。

## 4. 历史异常：保留原样，避免新产生

| 现象 | 证据 | 新版处理 |
| --- | --- | --- |
| 最终点框 | 1175、1344、77，共 3 个 | 只读保留历史；新建误点击记录尝试并删除，不留点框 |
| 最终框越出左 / 上边界 | 339 的 y1=-1；442 的 x1=-1；481 的 x1=-2；791 的 y1=-2 | 历史提示；新框限制在原图边界 |
| 空框 | 179 | 提交前确认；审计提示，不自动造框 |
| 最终框与事件框 1px 偏差 | 除框数不一致的一条外，4,596 个坐标中 2,299 个为 -1，2,297 个为 0 | 统一保存取整；不修改原始发布值 |
| 负指针坐标 | 245 个会话 | 不裁剪；图像留白映射是合理解释，但无法逐点还原旧 UI |
| 放大前后速度异常 | 数据说明提醒且记录可见 | 新运动段重置速度基线；历史值不重算 |
| 轨迹不能完全重放最终框 | 1344 | 显式报告，不猜测补事件 |

全量字段 / 事件结构检查 **0 条错误、8 条质量提示**。提示来自 3 条点框、4 条负边界框和 1 条空框。这里的“无错误”指本工具的数据结构验证通过，不表示所有证据语义都经人工复核；原图仅额外核对了 1001 和 1004 两张。

## 5. 从旧代码发现的问题

旧 main.py 把图片缩到最大 800 像素，再直接导出显示坐标。旧 bbox_canvas.py 没有区域缩放支持，编辑事件采用 move_start / resize_start，输出字段使用 instruction / type / final_bboxes，缺少 sample_id、question / answer、task_evaluation、source_dataset。不能仅改字段名就视为兼容。

此外还有：清空框会把整个 events 和起始时间一并重置；版本计数只存在内存，重启可能覆盖 v1；缺图时旧图仍留在画布；未保存导航在保存取消 / 失败时仍可能切题；窗口关闭没有草稿保护。新版在数据层、记录层、坐标画布、原子存储和界面流程分别修复，测试覆盖这些实际风险。

## 6. 维护者确认与未能恢复的部分

本次维护者明确确认：

- 右键区域缩放、左键选框；界面有恢复全图与删除选中框按钮。
- 初始可以看到整张图、没有图像滚动条，右键框选后看局部。
- 使用原图；不预先把素材压成低分辨率图片。
- **提交后才显示参考答案，不能提前看。**
- 提交时两个 0–1 滑条；提交后不自动跳题。
- 下一题任何时候可点，允许跳过。
- 提交、下一题、评分等控件的鼠标操作和坐标不记录。
- 鼠标离开画布时暂停鼠标采样和时钟，返回画布后继续累计有效时间，离开期间不计入标注时长。事件文件中的相对时间差不能单独证明画布外实际停留时间。

无法仅从最终数据唯一确定的内容：评分分界值在未观测区间的精确边界、当年的默认分数、所有快捷键、是否曾经自动保存、原视窗尺寸、完整速度计算细节，以及鼠标跟随关注区域或最小证据的具体人工培训措辞。

新版选择明确写进文档：评分边界 0.30/0.60、默认 0.50/1.00；采样节流约 100 ms；增加键盘快捷键、自动草稿、原子防覆盖、新零面积限制与运动基线重置。它们是本次修复 / 增强，不作为“已证明历史行为”来宣传。

数据与维护者确认支持完成一次真实搜索、标出所需证据、提交后查看答案。数据不能证明需要按 Z 字路线搜索、规定停留毫秒数、禁止修正、强制一次框准，或任何额外评分公式，因此新工具不把旧 README 的这些建议固化成硬性标注规范。
